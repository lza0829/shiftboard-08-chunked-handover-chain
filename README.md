# 06-shiftboard（交班台）

交班台 — 班次责任与在途批次交接：班次登记 → 在途批次归属 → 交班互斥办理 → 交班前后对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓贴源/明细/汇总分层。  
**也不是** OA 考勤排班后台、电商订单、报表 CSV 看板。

## 启动

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=%CD%\data
set FIXTURES_DIR=%CD%\..\fixtures
uvicorn app.main:app --host 127.0.0.1 --port 10600

# 前端
cd frontend
npm install
npm run dev
```

## 主链

登记班次与值班人 → 在途批次归属当前班次 → 发起交班（全仓同时仅一单进行中，可设分段上限 N）→ 在途快照一次性切成有序段链 → 按序逐段过户 → 计划级并集对账物化落档

## 分段交班链条（设计抉择，三处择一均已选定）

1. **计划与段的关系**：选「独立交班计划表 + 段交班单外键挂计划 id」。
   `handover_plans` 存计划（含发起时刻不可变快照 `snapshot_json`、分段上限 `segment_size`）；
   `handover_segments` 以 `plan_id` 外键挂计划，并加 `UNIQUE(plan_id, seq)`。
   发起时在同一事务里**一次性切出全部段**（每段至多 N 键），禁止只创建第一段却声称已切分。
2. **失败隔离**：选「段级独立事务提交」。
   每段过户在自己的事务里提交；上一段已完成才能办下一段（跳段 409）。
   任一段失败：本段过户整体回滚，后续段置「已阻断」，计划标失败；
   **已提交的前序段过户不回滚**——不存在任何回滚前段的代码路径。
3. **并集校验物化**：选「独立计划对账报告表」`plan_reconcile_reports`。
   发起切分时（阶段=发起切分校验）与计划终态（阶段=终态定案）各落一份：
   各段清单键的**集合并**与发起快照逐一比对（缺失/多出/段间相交），
   计划成功 ⟺ 每段成功 **且** 并集完整，禁止用各段成功计数加总冒充并集完整。

交班办理页展示计划、段链条状态与并集校验（终态后展示物化报告），全部落 SQLite，刷新后仍在。

## 界面约定

页面文案全部中文；入口：总览 / 班次 / 在途批次 / 交班办理 / 交班记录 / 交班对账。

## 与已有仓差异

| 仓 | 骨架 |
| --- | --- |
| Feedstitch | 多源解析→冲突隔离→水位 |
| Batchgate | 作业依赖→重试→水位 |
| Changeflow | 事件序→缺口→Sink 游标 |
| Checklane | 入检→规则→隔离签发 |
| Tiercraft | 贴源→明细→汇总→层间对账 |
| **本仓** | **班次归属→交班互斥→批次过户→交班对账** |
